## A. 先修：已經做好但沒在運作

- [x] **A1 排程分析每天失敗（9/28 起）** — 2026-10-03 修復：`/bin/bash` 加入完整磁碟取用權限後，由 launchd 觸發的每日簡報成功（161 秒，exit 0）。
  - 現象：`~/Library/Logs/infolink/*.launchd.err.log` 每天 `/bin/bash: …/scripts/claude-analysis.sh: Operation not permitted`。
  - 原因：專案在 `~/Desktop`、vault 在 OneDrive（`~/Library/CloudStorage`），兩者都受 macOS TCC 保護，launchd 啟動的 `/bin/bash` 沒有權限。手動在終端機跑沒問題（終端機有權限）。
  - 修法（需 Kenneth 本人操作）：系統設定 → 隱私權與安全性 → **完整磁碟取用權限** → 加入 `/bin/bash`（⌘⇧G 輸入路徑）。只搬專案離開桌面不夠，因為 vault 也在受保護的位置。
  - 驗收：`launchctl kickstart gui/$(id -u)/tw.infolink.daily-brief` 後 `daily-brief.log` 出現 `done`；隔天 08:35 有當日簡報、08:50 有開發活動分析。
- [x] **A2 LINE 推播未設定** — 2026-10-03 完成：`infolink:notify-test` 回報已送出。
  - 需 Kenneth：建立 LINE 官方帳號 → Messaging API channel → 取得 channel access token 與自己的 userId，填入 `.env` 的 `LINE_CHANNEL_ACCESS_TOKEN`、`LINE_USER_ID`。
  - 驗收：`php artisan infolink:notify-test` 手機收到訊息；之後 critical insight 與每日簡報摘要會推到手機。

## B. 新功能（依對管理的幫助排序）

### B1 結案作戰頁（交付 → 結案作戰）— 2026-10-03 完成

**要回答**：四個結案專案各自還差什麼、卡在誰、照現在的速度何時結得完、掛著多少錢。

- [x] 每個 `closing` 專案一張卡：目標日倒數、未結議題（依狀態：新建立／實作中／驗證中‧文豪／驗證中‧其他）、掛著的未收應收（含稅）、近 14 天每日未結數走勢（`redmine_status_snapshots`）、近 7 天平均每日淨消化 → **推估結案日**（對比目標日）。
- [x] 專案內的議題清單：依「卡在誰」分組（未指派／開發者／等文豪驗收／驗證中但不在文豪名下），可依停滯天數排序，連回 Redmine。
- [x] MCP 工具 `closing_projects`：同樣的資料給 Claude，每日簡報引用。
- 驗收：頁面上四案的未結數與首頁「結案專案進度」一致；推估結案日隨快照每天更新。
